# `coordinator`: one-page implementation contract

**Boundary and flow.** Private pnpm+Effect project, never a creativetoolkits feature. Carry distinct Effect-branded IDs through API/storage/native boundaries; unchanged primitive wires, no Agent Hub API. ATC is communication discipline, not another participant engine. Pi/omp plugin ↔ private Tailnet broker ↔ owned runner/native MCP child. GitHub/review → independent evidence; consented journals → spool → owner archive. Plugin owns identity/delivery, broker routing/ledger/evidence, runner slots/children, host journals. No automatic apply/merge/deploy.

**Runtime.** Exact published stable Effect/platform-node/sql-pg4.0.3, Kysely0.29.6 and Prisma8.0.0-rc.22; no snapshot or Effect3 downgrade. `Context.Service`/scoped layers own I/O. `contracts.ts` owns commands and wire/domain validation; generated database types own internal DB/select/insert/update contracts. Decode unknown RPC/config/filesystem/legacy SQLite/serialized TEXT-JSON seams once, never already-typed query rows. Broker/runner stateless `/mcp` uses2026-07-28; plugin-owned native control deliberately retains stateful2025-11-25. Both use installed native Effect MCP and official client2.3.1 Streamable HTTP with JSON/SSE, not deprecated standalone HTTP+SSE. Preserve incremental streaming/cancellation/backpressure, per-message bounds, bearer/Origin/protocol/media/session isolation and abrupt-close no-delivery ambiguity; configured concurrency is not measured throughput. `main.ts broker|runner`, `.ts` imports, Node≥22.19 and Node24 image. No `/rpc`, OAuth/resume, automatic apply/merge/deploy or task replay contract.

**Peer first.** Plugin enrolls machine/host/session/incarnation plus native session ID as worker. Broker restart requires fresh heartbeat. Only verified-live, actively polling, matching repo/worker gets offers. Receipt is not acceptance. Decline, unavailable/expired offer or explicit bypass permits runner dispatch; no offline mailbox. Fresh load guides choice; runner independently enforces capacity. Address/readback/confirmation/release require accepted bound peer ownership; runner-owned work never releases to stale peers.

**Durable dispatch.** Approved bounded request/task ID enters unique QUEUED ledger before queue offer; recovery repairs missing offers. Same ID/fingerprint is idempotent; changed material conflicts. Persist ASSIGNING/runner before acceptTask. Runner rechecks authoritative assignment/fingerprint/deadline after Git/transaction waits, then commits acceptance/material/worktree before reply/launch; only durable acceptance acknowledges queue claim. Pending admission journals return unknown/503, never not-accepted. Full/not-accepted stays queued without exhaustion. Timeout reconciles that runner; unknown blocks reassignment. Never rerun accepted work automatically. Restart resumes accepted-but-unlaunched work; uncertain child/prompt stays held with occupied capacity. Obsolete reports cannot starve others.

Kernel-held Linux `flock` owns journals, never persisted PIDs: duplicates fail closed, death releases ownership across PID-one/container restarts, and helper loss stops serving without later journal writes. Util-linux supplies `flock`/`setpriv`; GNU `env --chdir` preserves effective supervisor capabilities before dropping child privileges.

**PostgreSQL ownership.** Broker ledger/queue and the existing homelab runner journal require external PostgreSQL18, separate databases/roles and private canonical `databaseUrlFile` in both configs. Each has one session advisory-fenced owner and native Effect SQL transactions; runner work files additionally retain kernel flock. Generated Kysely queries compile through that owner; no second pool, automatic reconnect/retry or handwritten application SQL. PostgreSQL ownership loss stops database serving/writes and readiness, while cheap liveness stays200 and already-admitted native work survives until validated completion. Drain explicitly before restart; never replay uncertain work. Local kernel ownership loss remains a hard fence. Prisma emitted contract/attested migrations alone own schema, including `runner_tasks`/`runner_events`; startup verifies identity/queue/recovery readiness. SQLite runtime adapters/dependencies/workers are removed; `scripts/import-sqlite.ts` alone reads legacy SQLite offline. Preserve old homelab runner.sqlite until verified import, using a fresh PG state directory while retaining repositories/model/children/native sessions. The Mac has no Coordinator runner or direct SQL requirement: its plugin accesses the broker; native host SDK history is not Coordinator SQLite runtime. Historical [SQLite scheduling/contention research](docs/broker-concurrency-research.md) is not PostgreSQL acceptance or a claim that shared disk latency is fixed.

**Host CA trust.** Supplied `NODE_EXTRA_CA_CERTS` must name a valid public CA bundle at a canonical trusted path. Systemd persists it; remote SSH forwards the quoted path; native children do not receive it. Restart owner/client processes explicitly on trust changes, never export CNPG `ca.key`.

**Runner child isolation.** Trusted supervisor UID1000 has only CHOWN/DAC_OVERRIDE/KILL/SETUID/SETGID/SETPCAP; KILL supervises different-UID children. Each runner child uses a distinct reserved UID, zero capabilities/supplementary groups, NoNewPrivs, separate standalone repo/session/model HOME and model-only environment. Private enrollment/control/journal/parent environment/sibling work are inaccessible. Reserve non-overlapping million-UID ranges; retain acceptance rows. Model seed excludes histories/symlinks. Authorized proxy targets owned exact repo/ref/SHA child, not arbitrary sessions. Coordinator/broker exit preserves runner work; attach while channel lives. Lost stdio cannot imply completion/replay. Failed acquisition stays HELD; release capacity only after scoped physical closure. SDK deadlines/owner mismatches remain typed errors. Persist bounded identity/status metadata, never messages/thinking/tools/diagnostics. Native journals remain private host data. Peer-owned SDK sessions run inside the stock host process and retain that native user's filesystem privileges; SDK ownership is not a second OS sandbox.

**Addressed release.** Read back task/current worker, session/incarnation, message/revision, repo/ref/SHA, scope, restrictions, evidence and deadline; coordinator confirms current matching ready revision before prompt. Wrong ref needs correction/new readback; unable/clarify/hold carry reason, hold includes next-check. Confirmed release cannot reset through address/readback/instruction changes. Explicit old/new-session handoff reconciles acceptance, binds actual new worker and requires fresh readback/confirmation. Live/uncertain releases block handoff until known terminal outcome. Existing running work is not retroactively gated. Later approved native instruction needs new message/revision; immutable runner launch prompt never replays.

**Peer durability.** Commit bounded message/incarnation/short TTL before ack; replay unacknowledged delivery only to same incarnation. Recipient durably deduplicates before handling ack. Delete on ack/stop/TTL; offline sends fail. Lost ack allows redelivery, not exactly-once effects.

**Evidence.** Inspected repo ID, ref, full tested SHA and lanes bind read-only GitHub run/attempt/jobs. Newest relevant attempt must successfully complete every lane. Missing/API-loss/pending/skipped/cancelled cannot borrow old green; merge refs require authenticated current PR merge SHA, never source-head substitution. Latest local, CI, deployment environment/SHA and authenticated review retain separate provenance/time. SHA changes stale observations; same-SHA ref/lane changes stale CI. Polls preserve categories; 15s bounds headers/body/decode. Completion is not CI/deployment/approval. Evidence never authorizes execution/changes native task state; missing scoped credential means unknown, not broad PAT fallback.

**Consented archive.** Explicit session/every-participant consent precedes complete-line branch-aware scanning. `HostJournalEntry` projects metadata through one Effect schema; Effect Graph resolves parents across all complete lines, including later branches, and missing or incomplete parents record `unlinked`. Only entry IDs/parents/type/role enter bounded spool; content/tools/thinking/paths/credentials omitted, conversations unreconstructable. Async owner/session/entry/digest append is idempotent; record rewrite/overflow/missing/ephemeral/unlinked/content-omitted gaps. No logging model tool or turn-blocking network. Opt-out revokes before spool/row deletion; participant revocation removes enrollment/archive. Archive retention differs from peer TTL. Online snapshots erase archive/all-consent rows and VACUUM before dedicated-bucket SigV4 streaming. `objectBackup`: enforced-HTTPS/region/bucket/private0600 credential files, no 1Password API; Kubernetes Secret/other managers require no application change. `backup.ts` owns bounded S3 XML parsing: continuation tokens are opaque decoded text, including `]`, with strict snapshot keys and all pages validated before any deletion. Local mtime expiry runs at the one-minute snapshot cadence, before snapshot creation and remote work, not in one-second maintenance; remote failure cannot block that local pruning. Local/object expiry share retention; restore exclusive. Raw/temp/native/enrollment excluded. Unconfigured bucket/key means no durable-backup claim.

**Security/install/check.** TLS/enrollment/operation authorization, private Tailnet never Funnel; restricted paths/launchers/payloads, private0600 configs/tokens, rotation/redaction, append-only archive writer. Runner enrollment health/report-only; distinct control raw broker-only/hash runner-only, ledger-bound acceptance/release. Broker plaintext not E2EE. `pnpm install --frozen-lockfile`; `check` ([native-tsgo/Effect-lint](https://github.com/Effect-TS/tsgo#lsp-based-linter); warnings-visible, errors-fatal), `test`, `smoke`, `smoke:hosts`, `install:host --help`. `smoke:backup`: private `COORDINATOR_BACKUP_SMOKE_CONFIG`, loopback proof bucket. Native-user `--plugin-only`, root Linux `--runner-only`, trusted release/dedicated non-login account; Kubernetes bounded bootstrap. Registration/`-e` exclusive. Mac plugin-only. Homelab ai-dev-env PR/CI/ArgoCD verifies ESO/TLS/health/durability/gates/backup; no imperative deploys.

**Integration and deployment.** Private `main` source integration uses unmodified public SDKs from installed Pi1.0.4/OMP18.6.1. The plugin owns separate SDK sessions; it does not drive the surrounding TUI session through a void host API. Exact-commit normal CI remains required. Mac Ghostty keyboard/pixel acceptance and infrastructure/image deployment are not part of this source integration. No maintained-host forks, SDK rewrites/upgrades, global binary/profile replacement or automatic apply/merge/deploy. Kyverno-compatible legacy Cosign signatures/SLSA-v1 attestations and admission remain enforced; generated `dist/` artifacts are rebuilt, not committed.

**Plugin-owned SDK control.** `pnpm native:build` bundles Coordinator and the standalone runner extension while leaving the exact pinned SDK packages as runtime dependencies. Host manifests load only `dist/plugins/plugin.js`: its broker enrollment, control endpoint, transcript and lifecycle share one real SDK owner. The runner loads only `dist/plugins/native-plugin.js` with `--mode rpc --no-extensions`. Loading both entries into one host would create competing owners and is not supported. Each owner uses a private persistent `SessionManager`, its actual session ID, a fresh incarnation and isolated non-persistent settings. Extension discovery is disabled; OMP uses a fresh agent registry and the SDK's owner-routed async subsession option without replacing/disposing the host's manager, binding parent process state or inheriting MCP. Parent session lifecycle only creates/retires the owner. Native RPC stdout/stderr are drained privately, never parsed as MCP. The authenticated loopback endpoint is atomically published with private0600 credentials/configuration in a0700 directory. HTTP catalog/resource cursors retain their MCP-session and binding fences; private UTF-8 output remains byte-bounded and foreign generations are rejected. Busy/queue fields come from the owned SDK/controller; an unavailable exact async count is `null`, never an invented zero.

**Use the native host.** Build with `pnpm install --frozen-lockfile && pnpm native:build`, then register with `omp plugin link /absolute/coordinator` (Pi: `pi install /absolute/coordinator`). Start ordinary `omp` or `pi` in the target Git worktree; no Coordinator launcher is required. The plugin discovers its private0600 `PluginConfig` at `$XDG_CONFIG_HOME/coordinator/plugin.json`, or `~/.config/coordinator/plugin.json` when XDG is unset (`brokerUrl`, `tokenFile`, `machineId`, `stateDirectory`, `host`). `--plugin-only --plugin-config <file>` installs that configuration and registers the package without creating a wrapper. `COORDINATOR_CONFIG` is an optional absolute-path override, not a startup requirement. Missing default configuration leaves the plugin disabled; present insecure/malformed configuration fails closed. Optional `connectHosts` maps TLS hostnames to socket DNS targets inside the plugin only; certificate hostname verification remains intact and unrelated host traffic is unchanged. Coordinator creates a private native endpoint/token below its state directory; optional `COORDINATOR_NATIVE_CONFIG` selects explicit canonical paths for that owner. Registration and explicit `-e` loading are exclusive; do not load the standalone runner extension too. `/coordinator identity`, `inbox` and `help` expose owned SDK identity and private broker readback. OSC7501 remains root-agent TTY/TUI metadata; this is not Ghostty pixel proof.

**Dispatch holds and command cutover.** Held operations name the failing broker method, repository inspection or journal action with allowlisted cause categories and HTTP status; diagnostics omit exception messages, paths, credentials and payloads. Journal failed-write latches and uncertain-delivery no-replay remain intact. Existing processes retain their loaded plugin: rebuild/reload command clients before replacing their broker/runner servers with the stateless-only protocol; interactive native control is unchanged.

**Control recovery.** [Program-status/MCP/HTTP research](docs/control-recovery-research.md) now documents implemented control recovery, not a proposed timeout fix. Commands retain the 10-second deadline. Typed transport/timeouts and HTTP408/429/5xx except501 (unless the parsed JSON-RPC code is -32600 through -32603), plus presence-bound409/410, enter one owner-scoped exponential/jitter schedule (1,2,4,8,16, then30 seconds; local delays remain1–30 seconds). Transient recovery continues without an attempt-count cutoff while the owner stays active. A valid HTTP-date or delta-seconds `Retry-After` is a minimum and can exceed30 seconds. Other failures—including unchanged401/403,400/404/501, JSON-RPC codes -32600 through -32603, typed protocol errors, non-presence conflicts, and local repository/journal faults—pause broker traffic. Recovery re-enters through heartbeat then poll on the exact binding; only that successful pair resets outage state. The adapter does not retransmit a failed MCP request or whole tick; owner recovery makes a fresh heartbeat/poll pair rather than replaying a failed business operation. Acceptance-unknown work is not reassigned and accepted native prompts are never resubmitted. One outage warning and one recovery notice accompany the keyed `coordinator.network`/`coordinator.paused` status and capability-gated owned PSP record; the host root is never replaced or globally cleared. Pauses preserve accepted native work; retiring/replacing an owner interrupts its pending request/sleep, and a presence409/410 gets a fresh incarnation only after the old SDK can safely retire.

**Session discovery.** `/coordinator sessions` lists all known same-owner Coordinator participants across machines, not unrelated host sessions or saved chat history. The plugin automatically inspects the current worktree's selected Git remote; repository identity is presence metadata, not a session admission requirement. Authenticated session registration and listing need no repository enrollment, linking or per-repository plugin settings; the existing private plugin configuration remains persistent across sessions and worktrees. Each record includes native session/incarnation/worker, machine, Pi/OMP, repository, `live|stale` status and lease expiry. Live requires a verified unexpired lease and polling within10s; broker restart fences restored records as stale until enrollment/polling resumes. The broker's read-only `session.list` endpoint restricts results to the caller's owner, omits private principal/credential/conversation data, and returns stable session-ID cursor pages within the MCP byte budget. Session role and principal/incarnation bindings remain enforced; discovery does not grant task or runner execution authority. The plugin follows every page automatically; listing never approves or dispatches work.

**Correlated whole-run execution.** `native.prompt` acknowledges the actual public SDK admission under the caller's submission ID and an owner-local logical run ID; handled input has no run. Independent submissions wait in the owner's FIFO until SDK admission. Explicit streaming `steer`/`followUp` input is actually SDK-queued and shares the active logical run; queue-only controls require an active owned SDK turn. A final `completed|aborted|error` result requires the prompt promise, public idle/persistence barriers, SDK terminal event and final assistant stop reason. OMP additionally drains every owner-scoped async generation and admitted submission. Retries, compaction and continuation are not settlement. Cancellation clears unadmitted tickets/SDK queues, cancels owned OMP jobs and awaits real abort; acknowledgement alone is not an outcome. Missing proof retires the binding instead of inventing completion. Retained lifecycle metadata contains no conversation content. Broker delivery writes durable intent before SDK admission, never replays an uncertain revision, and reports the same owned binding/admission/final result. `SUCCEEDED` here means SDK execution completed; `evidenceVerified:false` explicitly leaves deliverable/CI/review/deployment proof separate.
