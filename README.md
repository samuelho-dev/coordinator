# `coordinator`: one-page implementation contract

**Boundary.** Separate private pnpm+Effect project, not a creativetoolkits feature. Retain omp task/worker/Agent Hub IDs and states; ATC is a communication discipline, not another participant, assignment or workflow model. Plugin owns local commands, session identity and delivery; broker owns routing, ledger and evidence; runners own slots, acceptance, worktrees and children. Host owns its native journal. No automatic apply, merge or deploy.

**Data flow.** Pi/omp plugin ↔ Tailnet broker (live directory, SQLite task/peer ledger and queue) ↔ macOS/Linux runner (journal, worktree, JSONL RPC child); GitHub polling and human review → task evidence; consented host journals → local spool → owner-scoped archive.

**Runtime.** Checked published and installed mutually compatible `effect@4.0.1`, `@effect/platform-node@4.0.1`, `@effect/sql-sqlite-node@4.0.1`; pnpm lockfile pins dependencies. Effect Schema validates bounded JSON RPC boundaries; one broker-local SQLite file holds task ledger and `PersistedQueue` SQL dispatch. Never network-share SQLite. Node must provide `node:sqlite` **and its online backup API**; installer probes the selected runtime, deployment uses Node 24. Effect does not supply product policy.

**Peer before dispatch.** Normalize selected Git remote to canonical repo key; reject ambiguous remotes. Key routes, never authorizes. Plugin enrolls authenticated machine/host/session/incarnation and heartbeats; broker restart leaves sessions unverified until fresh heartbeat. Offer work to a matching **live** owner via its active plugin connection first; delivery receipt is not acceptance. Only on decline, unavailable/expired offer or explicit bypass submit a worker task. No cold mailbox or assumption that saved sessions are live. Runner advertises fresh slots/load but checks local capacity.

**Dispatch.** Client-generated `taskId` and bounded approved request enter unique SQLite ledger as `QUEUED` before queue offer; recovery repairs missing offers. Same ID and fingerprint is idempotent; changed request conflicts. Record `ASSIGNING` and runner before `acceptTask`. Runner commits durable acceptance, approved launch material and worktree path before replying or launching; only then acknowledge queue claim. Full/not-accepted returns to queue without exhausting retries. On timeout reconcile that runner's journal; unknown acceptance blocks reassignment. Never rerun automatically after acceptance. Runner restart resumes accepted-but-not-launched tasks; uncertain child/prompt stays held.

**Child and follow.** Runner creates an isolated allowlisted Git worktree and supervises its own Pi/omp JSONL RPC child there. Broker-authorized proxy reaches **that child**, not arbitrary native sessions; separate-process socket smoke verifies owned-child status/attach, not general native cross-machine attach. Coordinator/broker exit does not terminate runner work; another authorized coordinator queries task/result and attaches while channel lives. On runner loss inspect journal/process; parent stdio may not be reattachable. Terminal worker status never implies CI, deployment or approval.

**Addressed work.** Address existing task ID, bound omp worker ID/session incarnation, message ID/revision, exact repo/ref, scope, restrictions, expected evidence and deadline. Receipt means handled delivery; worker reads back consequential details; coordinator confirms matching revision **before the substantive prompt**. Wrong ref requires correction/new readback. `unable`, `clarify`, `hold` (reason/next-check) prevent release. Handoff names old/new sessions and revision; new readback and confirmation follow reconciliation of old runner acceptance. Live/uncertain old acceptance blocks handoff. Already-running native work is not retroactively gated; later approved `task.instruction` on a bound native peer requires a new message/revision, readback and confirmation, never replays the immutable runner launch prompt. Keep compact fields on existing task row, not another engine.

**Peer durability.** Accept bounded content only for verified-live recipient; commit message ID/incarnation/payload/short expiry in SQLite before sender acknowledgement. Replay unacknowledged delivery to the **same incarnation** after disconnect/restart; recipient deduplicates and acknowledges handling, broker deletes on ack, stop or TTL. Lost ack can repeat delivery, not guarantee exactly-once effects. Reject new sends offline; no offline mailbox.

**Independent evidence.** Bind task to inspected GitHub repository ID, intended ref, full tested SHA and explicit required lanes. Read-only poll associates workflow run ID, attempt and jobs with exact repo/SHA. Latest relevant attempt must complete all required jobs successfully; missing lanes, API loss, pending rerun, skipped/cancelled jobs or PR-merge-SHA mismatch cannot borrow a green prior attempt. Show local tests, CI, separate deployment environment/SHA and authenticated human review with provenance/timestamps alongside runner result. New SHA stales older evidence; observations never authorize execution or change omp task state.

**Opt-in finalized journal.** Explicit session/participant consent precedes local complete-line Pi/omp JSONL scanning across branches. Capture is **metadata-only** (entry IDs, parents, type and role); content, tool arguments/results, thinking, paths and credentials are omitted before bounded durable spool. It cannot reconstruct a readable conversation or complete transcript. Asynchronously append owner-scoped entries idempotently by session/entry ID and digest; mark rewrites, overflow, missing/ephemeral/unlinked sources and omitted content as coverage gaps. No model logging tool or turn-blocking network call. Separate retention from peer TTL. Opt-out revokes enrollment before spool/row deletion. Online SQLite snapshots remove archives, enrollment and participant consent before entering the backed volume; raw journal-bearing data and temporary copies are excluded from backups, and sanitized snapshots expire.

**Security and acceptance.** Private Tailnet plus enrolled credentials and operation authorization on every call, peer reply, report and attach; public endpoints need TLS too. Restrict launchers/paths, payload sizes and file permissions; rotate credentials, redact logs, restrict archive writer to append. Broker sees plaintext: not end-to-end encryption. Install one backed-up supervised broker, durable macOS/Linux runner journals/worktrees and per-session plugins. Exercise real sockets: peer-first and replay/expiry; duplicate submit and restarts yield one child; full slots/ambiguous assignment never duplicate; correction/readback/handoff gate; exact-SHA reruns stay distinct from deployment/review; coordinator exit permits status/attach; unauthorized operations fail; archive gaps/deletion persist. Verify installed host lifecycle and JSONL RPC behavior, not undocumented APIs.

**Installation.** `pnpm install --frozen-lockfile && pnpm check && pnpm test`; `pnpm smoke` exercises real broker/runner/omp sockets; `pnpm smoke:hosts` proves native plugin discovery, commands, consent, inbox and session replacement on isolated synthetic sessions without model turns. Secure `COORDINATOR_CONFIG` JSON and separate credentials with mode 0600; broker config stores hashes. Native installation: `pnpm install:host -- --host omp --runtime /absolute/node --host-binary /absolute/omp --plugin-config /private/plugin.json --runner-config /private/runner.json` (use `--host pi` for Pi, `--dry-run` to inspect, `--remote SSH_ALIAS --remote-root /absolute/repo` for a preprovisioned reachable host). Installer uses native `omp plugin link`/`pi install`, an explicit config wrapper, Linux user systemd (user bus/linger required) or macOS GUI launchd. Explicit per-session `omp -e ./src/plugin.ts` / `pi -e ./src/plugin.ts` works **instead of** package registration; do not load both copies. Linux standalone omp 18.6.1/Pi 1.0.4 are runtime-tested; Pi 0.84.2 is source-checked, not Mac runtime proof. Never use Funnel; Homelab deployment follows ai-dev-env PR/CI/ArgoCD and central secrets/access/backup policy.
