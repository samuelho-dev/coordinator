## Observed dependency audit (2026-10-12)

A read-only enumeration of real, non-symlink package directories in the local pnpm store observed **263 installed package instances**, including stale versions, optional/platform packages, and development dependencies. This is an installed-store inventory, **not** a resolved production-image dependency closure. Every enumerated instance declared a license in package metadata: 152 MIT, 76 Apache-2.0, 15 BSD-3-Clause, 13 ISC, two BlueOak-1.0.0, and one each 0BSD, Unlicense, MPL-2.0, LGPL-3.0-or-later, and `(MIT OR CC0-1.0)`.

Concrete exceptions requiring attention:

- `@img/sharp-libvips-linux-x64` 1.3.4 declares **LGPL-3.0-or-later**, and its installed package root has no license file. Its actual README identifies a prebuilt native closure including cairo under MPL-1.1; fribidi, glib, libexif, libheif, librsvg, libvips, pango and proxy-libintl under LGPLv3; and additional permissive, patent and attribution terms. It states LGPLv3 use follows the “any later version” clause of LGPLv2/2.1. Review the accompanying `versions.json`, matching corresponding source, all notices, and any required replacement/relinking rights for the entire closure—not just libvips. Do not treat the containing MIT package as relicensing these libraries.
- `axe-core` 4.13.0 declares **MPL-2.0** and contains LICENSE plus LICENSE-3RD-PARTY.txt. Determine whether it is shipped in the resolved image/standalone executable; if shipped, preserve notices and satisfy source obligations for covered files and modifications.
- `onnxruntime-node` 1.30.0 declares MIT but lacks a root license file in the observed installed package. Audit its native binary/vendor closure separately.
- Several Pi and AWS package instances lack root license files. Metadata declarations do not replace required text/copyright retention; obtain matching-version upstream notices where missing.
- OMP's installed aggregate is a substantial generated notice collection (22,901 lines for the coding-agent package inspected), explicitly says it does not replace package-level licenses, and includes vendored code/assets/native third parties. It was inspected at its introduction and vendored brush/uutils sections; it was **not exhaustively audited** or proven to describe every byte embedded in the downloaded standalone executable.
- The inspected OMP aggregate excludes its own `@img/sharp-libvips-*` 1.2.4 assets because transformers is external, but Coordinator's production lock includes the optional transformers 4.3 → sharp 0.35.5 → libvips 1.3.4 path. That upstream exclusion is not evidence that Coordinator's added native closure is absent or covered by the aggregate. The aggregate also attributes `Silver.ttf` under CC-BY-4.0; retain applicable asset attribution rather than treating all bundled assets as MIT.
- Pi's installed HTML export assets contain copied `marked.min.js` 18.0.5 (MIT header, MarkedJS/Christopher Jeffrey copyrights) and `highlight.min.js` 11.9.0 (BSD-3-Clause header with an incomplete `undefined and other contributors` attribution). These embedded versions differ from the dependency graph's marked 18.0.11/highlight.js 10.7.3. Preserve their own headers and obtain matching complete license/copyright notices; Pi's root MIT metadata is not a substitute for the vendored BSD terms.

The image keeps dependency directories and their shipped license/notice files intact. It additionally collects matching-version OMP first-party/aggregate notices in a stable directory. This is notice preservation, not a legal sufficiency certification. BuildKit emits the image SBOM and provenance; release preparation retrieves them from the exact signed image rather than rebuilding. Reconcile that SBOM against this inventory and the standalone executable/native closure before public redistribution.

## Full-source/history boundary

Earlier CI/image configuration produced and copied a full-history `coordinator-source.bundle`; that is a historical observation, not a current artifact requirement. The generic repository cutover removed its runtime consumers, and current CI/Docker builds no longer produce or copy it. The runner clones each operator-configured repository at its pinned commit instead. The Coordinator image retains its exact source revision through OCI labels and trusted CI provenance; removing the obsolete bundle does not remove the public source/history audit prerequisite.

At the audited checkout, `git rev-list --count HEAD` observed **39 reachable commits**. A read-only historical path listing covered source, tests, scripts, dependency locks, README/research, Docker and workflow files. No complete whole-history secret-content scan, object-by-object confidential-material review, copyright ownership review, or embedded-asset audit was completed. The existing deployment research identifies historical operator-specific configuration/private infrastructure references; such identifiers are not, by themselves, evidence of a credential leak. **No leak is alleged or certified absent.** Before public repository visibility, review every reachable blob and retained ref, plus any release source archive; before public image distribution, audit the actual shipped source/dependency/native closure. Approve ownership and confidential-material findings and satisfy upstream notice/source obligations. Do not print credential candidates into workflow logs.

## Private preparation versus publication

`release.yaml` defaults to `prepare-private`: it verifies a successful trusted main CI run for the full source SHA, including the `supplementary`, `chart`, and `publish` jobs; retrieves that run's image and chart producer evidence; verifies the existing image signature/issuer/exact source provenance; retrieves SBOM/BuildKit provenance; and reuses the chart archive tested and packaged by source CI. The `chart` gate lints/renders generic broker-only and broker-plus-runner configurations and rejects missing/invalid required inputs. The requested stable SemVer must match both exact-source Chart.yaml and the packaged chart version (currently 0.1.0); future metadata-matched stable versions do not require workflow changes. Preparation checks the source gate's archive SHA256 and uploads workflow artifacts at existing repository visibility; in a private repository these remain private. The manifest records `chartOciDigest: null` until an actual OCI push exists; a chart archive SHA256 is not an OCI manifest digest.

Canonical upstream coordinates are `ghcr.io/samuelho-dev/coordinator` and `oci://ghcr.io/samuelho-dev/charts/coordinator`; forks derive their own repository image and owner chart namespace. Explicit `publish` publishes the chart and a GitHub release at existing visibility and signs only the chart. It never rebuilds or re-signs a foreign image, changes source/package visibility, modifies branch policy, deploys infrastructure, or enrolls workers. GitHub release visibility follows repository visibility; the workflow does not make a repository public. Existing chart/release versions are refused rather than deliberately overwritten.

**Public-ready status remains unestablished.** Required outstanding evidence includes complete dependency/native/standalone-binary notice/source compliance, full-history/confidential-material/ownership review, explicit owner-approved visibility changes outside these workflows, anonymous image/chart access checks, and independent supported Linux amd64 clean-install/upgrade/recovery acceptance. Nothing in this notice or a prepared release manifest certifies those steps.
